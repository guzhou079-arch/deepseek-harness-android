# 自建环境与出包（在手机上自己编译自己）

> 这个项目的核心价值**不在功能，在可维护性** —— 它能在手机上自己编译、自己打包、
> 自己签名、自己安装。这份文档讲怎么把这条链路跑起来。

## 一、先说清楚：构建环境不在包里，但**一键就能装**

| | 在哪 | 多大 |
|---|---|---|
| 主包（APK） | 发布页（GitHub / Gitee 都有） | 约 92MB |
| **构建环境** | **App 内按需下载** | 约 193MB（解压后 342MB） |
| 源码 | 本仓库 | 很小 |

为什么不做进主包：绝大多数人只是想用 AI，为 342MB 付体积和首启解压时间不划算。
想要自建能力的人，点一下就有 —— **不用为了照顾少数人让所有人都多背 342MB**，
反过来也**不该因为大多数人不需要就把这个能力砍掉**。

## 二、装构建环境（App 内一键）

**控制台 →「自建环境」→ 选 GitHub 或 Gitee**，等它下载 → 校验 → 解压 → 就绪。

两个渠道**内容完全一样**（都放同样的分卷，任选其一）。Gitee 单个附件有 100MB 硬限，
所以两边都用 3 个分卷 —— 不为任何一边做特例。

它做的事：
1. 读清单 → 逐卷下载（**已下且校验通过的卷会跳过**，可断点续传）
2. 逐卷校 sha256 → 合并 → 再校**整包** sha256
3. 用内置的 python3 解压（`filter='fully_trusted'`，**保证符号链接和权限位还原**）
4. 落到 App 私有目录，写就绪标记

⚠️ **必须解压到内部存储**：`/sdcard` 是 FUSE，**存不了符号链接**，
而 Alpine rootfs 里有 **918 个符号链接**（比普通文件还多）—— 放上去就是一堆坏链接。

✅ 分卷会留在 `/sdcard/DeepSeekHarness/buildenv`，所以**重装 App 后只需重新解压，
不用重新下载**。

## 三、自己出包

装好之后，在源码目录里跑 `selfbuild/` 脚本。**路径可配** —— 换目录也能跑：

```sh
cd <你的源码目录>                    # 不必是 /sdcard/Download/Operit/dsh_own_app
export DSH_PROJECT="$PWD"            # 可选，默认从脚本自身位置推导

sh selfbuild/scripts/javac-app.sh                                  # App 侧 Java → classes.dex
sh selfbuild.sh payload && sh selfbuild.sh patch                   # 导出 payload + 套 overlay
sh selfbuild.sh pack --dex work/appbuild/out/classes.dex           # 打包
sh selfbuild.sh version 1.29 61                                    # ⚠️ 版本号要显式设
sh selfbuild.sh sign                                               # 用你自己的钥匙签名
```

### ⚠️ 几个必须知道的坑（都是踩出来的）

- **签名钥匙别弄反**：装机包用「设备认可的那把」，发给别人的发行包用发行钥匙。
  用错会导致对方**无法覆盖安装**，而"卸载重装"会清空他的所有数据。
- **版本号必须显式设**：不设就沿用骨架的旧版本号 → **更新检查失效**，
  而且 `versionCode` 低于用户已装的那份时 `pm install -r` 会**因降级被拒**。
- **出包会覆盖本地改动**：`build-overlay/` 里的文件会覆盖运行副本。
  典型受害者是**背景图的加载注入**（它写在 `dsh-client-ui-open-in-app/lib/client.js` 里，
  而这个文件同时在 overlay 中）—— 缺了它背景图完全不显示。
  现在 `patch` 步骤会**自动校验**，缺了直接让出包失败。
- **⛔ 别拿自己出的包直接装机**：先在隔离实例里验证，并把当前 APK 备份到 `/sdcard`
  留作回滚。这条是血的教训（详见 `docs/PATCH-NOTES-v1.28-postmortem.md`）。

## 四、环境损坏了怎么恢复

App 内重新点「自建环境 → 用 … 重新安装 / 修复」即可（分卷还在就很快）。

手动恢复：tarball 就在 `/sdcard/DeepSeekHarness/buildenv/`。
解压后有两个**容易漏的点**：

1. **必须解压到 App 私有目录**（`/data/user/<id>/<pkg>/files/`），不能放 `/sdcard`
2. **必须建出 `work/linux/tmp`** —— `run.sh` 里 `PROOT_TMP_DIR` 指向它，
   不存在时 proot 会直接 `can't create glue rootfs` 退出

```sh
F=/data/user/0/com.deepseek.harness/files
python3 -c "import tarfile,sys; tarfile.open(sys.argv[1]).extractall(sys.argv[2], filter='fully_trusted')" \
  /sdcard/DeepSeekHarness/buildenv/dsh-buildenv-v1.tar.gz "$F/tmp/restore"
mv "$F/tmp/restore/env/work/linux" "$F/work/linux"
mkdir -p "$F/work/linux/tmp"                       # ← 少这步 proot 起不来
cp "$F/tmp/restore/env/toolchain/"*.jar "$F/toolchain/"
sh "$F/work/linux/run.sh" java -version            # 验一下
```
